# 📜 명심코칭 백업 정책 및 데이터 수명주기 규정 (Backup Policy)

## 1. 목적 및 철학
명심코칭의 백업 철학은 **"무조건 모든 데이터를 영구히 쌓아두는 것"이 아니라, "복구 가능한 형태로 안전하게 보호하되, 개인정보 보호 원칙과 삭제 권리를 침해하지 않는 것"**입니다.
백업 보존 정책은 개인정보 처리방침(Privacy Architecture)과 반드시 일치해야 하며, 사용자가 삭제한 개인 데이터가 백업 복원으로 인해 무기한 살아남아서는 안 됩니다.

---

## 2. 데이터 계층별 보존 기간 (Retention Rules)

| 계층 | 데이터 명칭 | 보존 기간 | 암호화 요건 | 접근 권한 |
| :--- | :--- | :--- | :--- | :--- |
| **Tier A** | **Canonical Product Data** (200+ 카드, 라우터, 안전) | 영구 보존 (릴리즈 태그별 스냅샷) | 저장 시 암호화 (AES-256) | ADMIN, EDITOR |
| **Tier B** | **Private User Data** (SCAN, 행동실험, 여정 일기) | 30일~90일 (사용자 요청 시 즉시 파기) | 종단 간 암호화, 엄격 분리 | 본인 브라우저 격리 |
| **Tier C** | **Aggregated Data** (일일 통계, 익명 신호) | 1년 (메타 집계치만 보존) | 표준 스토리지 암호화 | ADMIN, REVIEWER |
| **Tier D** | **Rebuildable Data** (검색 인덱스, 캐시) | 보존 불필요 (필요 시 재생성) | 불필요 | SYSTEM |
| **Tier E** | **Secrets / Config** (API 키, 서명 토큰) | 로테이션 주기(90일)에 맞춰 파기 | 시크릿 매니저 전용 | 최상위 ADMIN |

---

## 3. 사용자 삭제(User Delete)와 백업 간의 조화

1. **프로덕션 즉각 삭제**: 사용자가 개인 기록을 삭제하면 프로덕션 로컬 스토리지에서 즉시 소거됩니다.
2. **삭제 원장(Deletion Ledger) 기록**: 재해 복구 시 과거 백업본에 포함된 삭제 데이터가 복원되는 것을 방지하기 위해, 식별자와 타임스탬프만 포함된 최소 삭제 원장을 유지합니다.
3. **백업 유효기간 만료 시 완전 파기**: 과거 백업 세대는 보존 기간(최대 30일)이 경과하면 자동 폐기되어, 삭제된 데이터는 영구 소멸합니다.
