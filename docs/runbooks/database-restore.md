# 💾 데이터베이스 복원 및 무결성 검증 런북 (Database Restore Runbook)

## 1. 개요
데이터베이스 손상(Corruption), 관리자 실수에 의한 데이터 유실, 비정상 마이그레이션 실패 시 안전하게 데이터를 복원하는 절차를 정의합니다.

---

## 2. 복원 실행 수칙

### 1단계: 격리 환경에서 복원 (Isolated Environment)
- 프로덕션 DB에 직접 덮어쓰지 않고, 복원 전용 스테이징 DB 또는 로컬 격리 네임스페이스에서 복원을 선행합니다.

### 2단계: 체크섬 및 레코드 수 대조
- 스냅샷 메타데이터의 `recordCount` 및 `checksum`과 복원된 데이터셋의 산출값을 대조합니다.
- 불일치 시 복원을 즉시 중단하고 이전 세대 백업본을 선택합니다.

### 3단계: Deletion Replay 실행 (필수)
- 복원된 사용자 테이블에 `myungsim_backup_deletion_ledger`의 삭제 툼스톤을 대조합니다.
- 삭제 대상 레코드를 프로덕션 반영 전에 완전히 퍼지(Purge)합니다.

### 4단계: 교차 격리 및 안전 검증
- 합성 사용자 A와 B의 계정으로 로그인 테스트를 수행하여 상호 데이터 간섭이 없는지 확인합니다.
