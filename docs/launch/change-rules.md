# MYUNGSIM 30-Day Change Rules (변경 통제 규칙)

## 1. 개요
공개 후 30일 동안 서비스의 일관성과 데이터 신뢰도를 유지하기 위해, 모든 코드 및 콘텐츠 변경은 본 규칙에 의해 엄격히 제한됩니다.

---

## 2. 변경 분류 및 처리 기준

| 등급 | 정의 | 30일 기간 내 조치 지침 | 승인 절차 |
|---|---|---|---|
| **P0 (치명적 결함)** | 서비스 중단, 개인정보 누출, 자해/타해 안전 라우팅 미작동, DB/스토리지 손상 | **즉각 수정 (핫픽스)**. 사전 관제 동결 규칙 예외 적용. | 시스템 리드 + 프로덕트 오너 즉시 승인 |
| **P1 (주요 결함)** | 핵심 기능(1-Minute 코칭, 카드 열람) 불가, 치명적 콘솔 크래시 | **24시간 이내 수정**. 최소 범위 격리 패치. | 기능 담당 엔지니어 + QA 승인 |
| **P2 (개선/편의)** | 특정 UI 여백, 검색 결과 정렬 순서 불만족, 문구 어색함 | **변경 금지**. 30일 차 회고 전까지 동결(Frozen). | 리뷰 대기 목록(Watch List) 등록 |
| **P3 (신규 기능)** | 신규 PACK 추가, 신규 심리검사, 게이미피케이션 | **전면 금지**. 30일 기간 내 개발/배포 일체 불허. | 거버넌스 위원회 정기 회의 상정 |

---

## 3. 핫픽스 적용 4대 수칙
1. **최소 변경의 원칙**: 보고된 결함을 해결하는 데 필요한 최소 라인의 코드만 수정합니다.
2. **회귀 테스트 필수**: 수정 후 기존 26개 E2E 테스트 및 안전 라우팅 테스트 전수 통과 확인.
3. **P0 롤백 대비**: 수정 사항이 부작용을 일으킬 경우 1분 이내에 이전 커밋으로 즉시 롤백 가능해야 함.
4. **기록 보존**: 모든 변경은 `reports/launch-change-log.md`에 변경 이유, 영향도, 승인자를 기록.
